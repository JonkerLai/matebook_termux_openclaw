## 版本 A：60 秒短视频（抖音 / 视频号 / 小红书）

### 开场（0–5s）

> 一台要吃灰的平板，我把它改造成了 24 小时在线的 AI 服务器。
> 不 root，不刷机，现在我用微信就能指挥它干活。

**画面**：平板特写 → 手指点开 Termux → 服务列表刷出来

### 痛点（5–15s）

> 为什么想起这个事？
> 我有一台安卓平板，买来只用来爱奇艺。
> 但它其实有 8 核 CPU、8G 内存、229G 存储 —— 这配置比很多云服务器都强。
> 唯一的限制是：它不能 root。

**画面**：平板配置页 / 存款空间截图

### 做了什么（15–40s）

> 于是我做了三件事：
>
> **第一，绕过安卓的限制。**
> 安卓会在后台冻结 App，我就关掉电池优化、加唤醒锁、关掉幽灵进程杀手。
> 现在它连续跑一整天，一次都不掉线。
>
> **第二，把服务拆成模块。**
> 9 个服务：SSH、AI 网关、文件服务、记忆库、公网隧道、看门狗……
> 每个一个脚本，`./start.sh` 一把梭，`./status.sh` 一眼看全。
> 哪个挂了，看门狗 60 秒内自动拉起。
>
> **第三，打通入口。**
> 微信能对话、浏览器能开面板、Windows 上挂成 Y 盘、手机能连 SFTP。
> 外面用 4G 也能访问，走 Cloudflare 隧道，不用公网 IP。

**画面**：终端滚动启动日志 / status.sh 全绿 / 微信对话界面 / 资源管理器 Y 盘

### 高潮（40–50s）

> 最爽的是什么？
> 我在外面用手机微信发一句「查一下平板还剩多少电」，
> 它真的会去调安卓 API，把电量、温度、充电状态读出来告诉我。
> 这台平板，现在是我的远程服务器、文件中心、和个人助理。

**画面**：微信对话（问电量 → 回复百分比）/ 平板电量界面

### 结尾（50–60s）

> 代码已经开源，包括完整的踩坑记录。
> 评论区扣「平板」，我把仓库地址发你。
> 别让你的旧设备吃灰了。

## 版本 B：3 分钟中视频（B 站 / YouTube）

### 0:00–0:20 开场

> 这是一台 2020 年的安卓平板。
> 过去三年它的用途是：盖泡面、看剧、垫桌角。
> 但从今天起，它是一台 7×24 小时在线的 AI 服务器 ——
> 我用微信就能指挥它。

**画面**：平板拿起来，屏幕亮，打开 Termux

### 0:20–1:00 为什么要做这个

> 云服务器一个月 50 块起，配置还不如这台平板。
> 而且数据在别人机器上，我总有点不放心。
>
> 安卓平板的问题是：它是消费级设备，不是服务器。
> 系统会冻结后台、会杀进程、会限制端口。
> 但这些都是**策略**问题，不是**能力**问题 ——
> 只要绕过策略，它就是一台 ARM 服务器。

**画面**：CPU-Z 配置 / 后台冻结的设置页 / 服务运行截图

### 1:00–1:40 三个核心技术点（重点讲）

> **第一个坑：X server 被冻结。**
> 我一开始想装个 Linux 桌面，结果画面老是卡死。
> 排查半天发现：X server 是 Termux 的子进程，
> 安卓一冻结 Termux，X server 跟着停。
> 解决办法不是改软件，是改系统设置 —— 应用启动管理设成手动。

**画面**：卡死的桌面 → 设置界面 → 正常运行的桌面

> **第二个坑：子进程超过 32 个就被杀。**
> 这是 Android 12 的幽灵进程杀手。
> 一个 Node 服务随便就几十个线程，所以 Termux 会莫名其妙重启。
> 用 adb 关掉这个策略，世界清净了。

**画面**：adb 命令执行 / Termux 稳定运行时长

> **第三个坑：定时任务死循环。**
> 这个最坑 —— AI 突然不回复了，CPU 跑满，日志一小时涨到 38 MB。
> 原因是一个定时任务在疯狂报错：它需要「进程启动标识」，
> 而安卓的权限拿不到。每两秒重试一次，把事件循环占满了。
> 关掉定时任务，立刻恢复。

**画面**：日志刷屏 / 关闭 cron / 恢复正常

### 1:40–2:30 成品演示

> 现在的成品长这样：

**演示 1：微信对话**
> 「帮我看看平板现在多少度、还有多少电」
> → 它调安卓 API，把数据读出来

**演示 2：网页面板**
> 电脑打开面板，完整的聊天界面，还能看工具调用过程

**演示 3：文件挂载**
> Windows 里挂成 Y 盘和 S 盘，
> Y 是 Termux 家目录，S 是手机存储，照片直接拖拽

**演示 4：自愈**
> 我故意把服务全停掉 → 关掉看门狗 → 手动重启
> 看，130 秒后全部自动恢复

### 2:30–3:00 结尾

> 整个项目的代码、文档、踩坑记录都开源了。
> 不只是脚本，还有：
> —— 每一步为什么这么做
> —— 遇到什么错、怎么解的
> —— 哪些是安卓平台的硬限制，别浪费时间试
>
> 如果你也有吃灰的安卓设备，试试看。
> 它可能比你想象的能干。

## 拍摄建议

### 镜头清单

| 场景 | 要点 |
|---|---|
| 平板特写 | 屏幕要亮，避免反光 |
| Termux 终端 | 字体调大（14–16pt），关掉深色主题切换 |
| 服务启动 | 录屏，后期加速 2× |
| status.sh | 停留 2 秒，让观众看清「全绿」 |
| 微信对话 | 手机录屏，注意打码 |
| 资源管理器 | 显示 Y: / S: 两个盘 |

### 打码清单（重要）

| 要打码 | 原因 |
|---|---|
| Token / API Key | 泄露 = 别人能用你的额度 |
| 公网隧道地址 | 泄露 = 别人能访问你的服务 |
| IP 地址 | 至少遮住最后一段 |
| 微信昵称头像 | 隐私 |
| 文件夹里的私人文件名 | 隐私 |

### 节奏建议

- **前 3 秒必须有钩子**（吃灰平板变服务器）
- 技术细节**不要超过总时长的 40%**
- 每个技术点配一个**可视化结果**（全绿状态、恢复日志）
- 结尾一定要给**行动号召**（评论 / star）
